# Battery Management System (BMS) Edge AI Classifier

An optimized Edge AI application designed to classify battery health status into **LOW**, **NORMAL**, or **HIGH** categories based on real-time voltage, current, and temperature sensor readouts. 

This implementation is specifically structured and cross-compiled to run within an embedded Linux deployment ([Linux4SAM](https://microchip.com)) targeting the **Microchip SAM9X60-Curiosity REV 4** platform.

---

## 🏗️ Hardware Architecture & Constraints

Deploying machine learning models to legacy hardware presents extreme design bottlenecks. The **SAM9X60-Curiosity** hardware configuration imposes several key limitations that this codebase addresses:

* **Processor Architecture:** ARM926EJ-S core running at a peak clock rate of **600 MHz** (ARMv5TEJ instruction set).
* **Vector Extensions:** Lacks ARM NEON SIMD engines. Complex calculations must execute step-by-step.
* **Floating Point Capabilities:** Lacks a dedicated hardware Floating Point Unit (FPU). Floating-point decimal operations are computationally heavy as they are emulated in software.
* **On-Board Volatile Footprint:** 128 MB External DDR2 SDRAM System-in-Package (SiP).

### 💡 The Edge Impulse Optimization Workaround
Because standard Edge Impulse Linux binaries rely on modern ARMv7-A/ARMv8-A extensions (such as NEON) that cause immediate application crashes (`Illegal Instruction` core dumps) on an ARM9 chip, this codebase uses a highly optimized workaround:
1. The model configuration profile mimics a raw **Cortex-M0+ Microcontroller (MCU)**.
2. The compilation targets basic **ARMv6-M** assembly layout.
3. The pipeline drops hardware dependencies and utilizes the **Edge Impulse EON™ Compiler** to convert neural layers into pure, clean C++ loops.
4. Memory usage is optimized to fit inside the 128 MB RAM boundary safely alongside the Linux kernel layer.

## 🛠️ Step-by-Step Deployment & Compilation Guide

Follow these sequential steps directly inside your SAM9X60 Linux terminal (via SSH or Serial Debug Port) to construct and run the executable application block:

### 1. Unpack the Edge Impulse Environment
Move your project components into your working workspace directory and extract the core framework dependencies:
```bash
cd /root
mkdir -p bms_edge_ai
mv main.cpp bms_edge_ai/
mv edge_impulse_model.zip bms_edge_ai/
cd bms_edge_ai

# Extract the C++ framework files
unzip edge_impulse_model.zip
```

### 2. Compile Natively on the SAM9X60 Linux Kernel
We execute the native build phase directly on-board using the GNU C++ compiler (`g++`). 
We explicitly pass the maximum optimization flag (`-O3`) which forces the local compiler to restructure matrix math pipelines specifically for the individual registers of the 600 MHz ARM9 core:

```bash
g++ -O3 -std=c++14 main.cpp \
edge-impulse-sdk/dsp/kissfft/*.cpp \
edge-impulse-sdk/dsp/dct/*.cpp \
tflite-model/trained_model.cc \
-I. -o bms_runtime
```

### 3. Run the On-Device Application
Execute the compiled binary artifact:
```bash
./bms_runtime
```
